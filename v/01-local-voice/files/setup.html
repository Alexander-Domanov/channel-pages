Setting it up

Six steps. After each one there is a line telling you what you should see. If you don't see it, stop there — the next step won't work on top of it.

First, what computer do you have?

The steps are the same everywhere. Two places differ: how you install Python, and one line in the OmniVoice install.

  • Mac. Everything below is written the way it looks on macOS.
  • Windows. Install Python from python.org and tick Add python.exe to PATH on the first screen of the installer. In the terminal, use py where the lines below say python3.
  • Linux. Python is usually there already. Check it before installing another: python3 --version. Anything older than 3.12, get a newer one.

What is tested, and what isn't. I ran both programs on a Mac with an M2 chip and 8 GB of memory. That path is tested by me. The Windows and Linux lines I took from the two projects' own installation pages and from Python's own manual, linked at the bottom — I did not run them. If something doesn't match what you see, trust their page over this one.

Step 1 — Python 3.12 or newer

Install it from python.org and take the default options. Then check what you actually got:

python3 --version

You should see Python 3.12 or higher. Whatever number python.org hands out now is fine — 3.12, 3.13, 3.14. Three other answers mean three different things:

  • An older number, like 3.9.6. That's the copy Apple ships for its own tools, and Python's manual says leave it alone. The one you just installed sits behind it. Open a new terminal window and check again — the installer only takes effect in windows opened after it.
  • The old number again in a new window. Your new Python is installed but not first in line. Call it by its full path instead of python3 — here and in step 2. On a Mac that path looks like /Library/Frameworks/Python.framework/Versions/3.14/bin/python3; the version folder is the number you installed, and ls /Library/Frameworks/Python.framework/Versions/ shows what's there.
  • command not found. Nothing is installed yet. Run the python.org installer, open a new terminal window, check again.

Our own Mac took a different road: its Python 3.12 came from uv, a tool that installs Python itself. The paragraph above is the official path, not the one we ran.

Step 2 — a folder of its own for each program

This is the step people skip, and the one that breaks things a week later. Both programs need different versions of the same shared piece of maths. Put them in the same place and they break each other.

A folder that holds one program and its parts is called an environment. One program, one environment.

Now, where these lines go. A terminal is a window where you type commands instead of clicking. Open it:

  • Mac: press ⌘ and Space together, type Terminal, press Enter. Or Finder → Applications → Utilities → Terminal.
  • Windows: press the Windows key, type PowerShell, press Enter.
  • Linux: Ctrl + Alt + T.

Everything from here on goes into that window: one line, then Enter, then the next line. Four lines make a folder, step into it, and put a copy of Python inside:

mkdir omnivoice
cd omnivoice
python3 -m venv .venv
source .venv/bin/activate

On Windows the activation line depends on which window you opened:

  • PowerShell: .venv\Scripts\Activate.ps1. If it answers that running scripts is disabled on this system, run Python's own fix once, then try again: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser.
  • Command Prompt: .venv\Scripts\activate.bat. This window doesn't change the prompt, so check with pip list — a short list of packages and no error means it worked.

You should see the environment name in brackets at the start of your prompt: (.venv). Everything from here happens in this window. Close it and nothing is lost — open a new one, go back into the folder and activate again. Lost your place? pwd prints the folder you're standing in.

The Windows lines come from Python's manual and the projects' own instructions; I haven't run them. The Mac lines I ran.

Step 3 — the maths part, then the program

pip install torch==2.8.0 torchaudio==2.8.0
pip install omnivoice

On Windows or Linux with an NVIDIA card, don't type the first line — take it from pytorch.org. The wrong build either fails outright or quietly falls back to the slower processor.

You should see a run of "Installing collected packages" lines, then "Successfully installed". Nothing to read while it works. That's normal, and it can take a few minutes.

Step 4 — Qwen3-TTS, in its own folder

cd ..
mkdir qwen3-tts
cd qwen3-tts
python3 -m venv .venv
source .venv/bin/activate
pip install -U qwen-tts

You should see the same "Successfully installed" line. If the environment name in your prompt says omnivoice, you're in the wrong folder — check Step 2.

Step 5 — a first run, before your own voice

Don't record anything yet. One line and the program speaks in a random voice — nothing of yours is involved, so nothing of yours can be the problem.

omnivoice-infer --text "This is a test for text to speech." --output hello.wav

The first run downloads the model — a few gigabytes, and the slow part. Then play hello.wav.

You should see pages of download lines, then a line saying where the file was written. You should hear a voice you've never heard, reading that sentence. No file? Read the last red line in the terminal.

Step 6 — your sample, then your own words

Record ten seconds of yourself — eight rules on recording your sample — and save it as my_voice.wav in the folder you're working in. The format matters: a phone memo usually lands as .m4a, and the sample page lists three ways to deal with that. Then point the program at it — one command does the whole job:

omnivoice-infer --text "This is me talking, not a robot." --ref_audio my_voice.wav --output mine.wav

Two things you can add:

  • Tell it what's in your sample. Type the words you recorded and it stops guessing: --ref_text "the words you actually said". Leave it out and it transcribes your recording by itself.
  • File somewhere else? Give the whole path: --ref_audio ~/Desktop/my_voice.wav.

Rather click than type? omnivoice-demo --port 8001 opens the same thing in a browser: the Voice Clone tab, your text on top, the file in Reference Audio, then Generate.

You should hear your voice reading the text you typed. That's the whole thing working — every video after it is script, paste, wait.

Six that stop you

  • python3: command not found, or python is not recognized. Python isn't installed, or it isn't on PATH. On Windows, reinstall and tick Add python.exe to PATH, then open a fresh terminal.
  • pip: command not found. The environment isn't active. Activate it again (Step 2) and run the same line.
  • No module named .... You're in the other program's folder. Look at the name in brackets in your prompt — two programs, two environments.
  • A CUDA error. That's the NVIDIA build of the maths part. Get the install line from pytorch.org again instead of typing it from memory.
  • Out of memory. Close other programs, try a shorter piece of text, then the smaller model. In my test the peak stayed under two gigabytes on an 8 GB Mac, so memory wasn't the limit there — but your machine, your settings and your version of the maths library can behave differently.
  • Permission denied. Something is trying to write outside your environment. Start a clean folder and repeat Step 2 in it.

If it looks stuck, sounds wrong, or stays silent

  • It prints pages of text and looks stuck. That's the download. Leave it.
  • The voice sounds flat or rushed. That's the sample, not the settings. See recording your sample.
  • Nothing comes out at all. Nine times out of ten the sample file is missing, or the path to it is empty. Check that first.
  • Still stuck? Both projects keep their own instructions — OmniVoice, Qwen3-TTS. Search there for the exact red text you got.
